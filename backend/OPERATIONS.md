# 人工开通与运营管理（0.20.67，2026-10-20）

本轮为本地实现，尚未部署服务器。没有真实支付、自动到账、余额钱包或供应商账单接入；也没有修改现有用户、真实密码或额度。邮箱未配置时，可由管理员在现有用户页创建个人账号，再单独设置套餐和有效期。

## 数据一览

管理员登录后，`GET /v1/admin/operations?month=YYYY-MM` 按 **UTC 月份** 汇总完整调用表，不沿用旧预览的 200 个用户或 100 条调用截断。包括每用户每应用的请求数、输入/输出/总 Token、语音秒数、图片数、联网搜索次数和待核对调用数；模型汇总与全站汇总使用同一统计口径。

权限与基础额度展示当前设置；历史月份的“总额度”是 **当前基础额度 + 该月人工增加的额度**。旧系统没有每次基础额度变更的完整快照，不能据此重建当时的额度比例。接口中的 `quota_note` 提醒这一限制。

提醒包括：已暂停、已到期、七天内到期、请求或音频用量达到 80%、上游调用待核对。到期与暂停提醒采用当前时间；未知调用仍计入请求额度，避免重试导致超额。

## 费用估算

`POST /v1/admin/cost-rates` 仅管理员可配置：

```json
{
  "model": "模型标识",
  "currency": "CNY",
  "input_per_million": "2.0000",
  "output_per_million": "4.0000",
  "audio_per_minute": null,
  "web_search_per_call": null
}
```

以上数字仅为接口格式示例，不代表任何供应商实际价格。费率为非负十进制字符串，最多八位小数；缺省或 `null` 表示未知。至少填写一项。`effective_from` 可选 Unix 秒，默认服务器当前时间，只能设置现在或未来。版本只能追加，不允许回填过去价格或覆盖相同模型/相同时间的旧版本。每次调用按 `calls.created` 匹配当时已生效的最后一版费率。

成本字段：

- `estimated_cost_cny`：所选范围全部已核对且所需费率全部已知才返回数值字符串，否则为 `null`。
- `known_cost_cny`：仅已能计算的调用小计，不代表完整成本；必须结合覆盖率展示。
- `priced_calls`、`unpriced_calls`、`pricing_coverage`：可估算调用数、无法估算调用数和调用覆盖比例。
- `pricing_complete`：是否完整；`actual_billing_connected` 始终为 `false`。

未配费率、历史费率不存在、调用待核对、所需工具/语音费率未配置，均不能当作 0 元。只有管理员明确配置 0，或完全没有调用，才可能得到真实的估算 0。

公式为输入 Token × 输入单价 / 百万 + 输出 Token × 输出单价 / 百万 + 语音秒数 × 每分钟单价 / 60 + 搜索调用数 × 每次单价。图片数量仅供观察，已经计入输入 Token 时不重复加价。

费用仅是 **按配置单价估算**，未包含缓存折扣、价格阶梯、供应商活动或优惠，实际以供应商账单为准。当前调用表没有完整保存缓存细分与阶梯计价信息，不能把估算称为实际账单。参考官方 [Responses API](https://docs.volcengine.com/docs/ark/create-model-responses-api?lang=zh) 与 [上下文缓存](https://docs.volcengine.com/docs/ark/context-cache?lang=zh)。

## 人工额度台账

`POST /v1/admin/credits`：

```json
{
  "user_id": 12,
  "app": "zhiyun-subtitles",
  "request_credit": 100,
  "audio_credit_seconds": 600,
  "kind": "gift",
  "amount_cny": null,
  "note": "人工赠送体验额度",
  "idempotency_key": "每次操作生成的UUID"
}
```

`kind` 为 `gift`（赠送）或 `manual_payment`（人工登记已收款）。收款金额可空；空值不能当作已收 0 元。赠送不能填非零收款金额。金额最多保留两位小数。至少增加一种额度；不支持负数、扣款或退款。

独立台账记录操作者、目标用户、应用、UTC 月份、收款类型与金额、备注、前后总额度。增加的额度叠加在 **当前 UTC 月的总限额** 上，不清零已用量，不修改基础套餐，月底自动失效，不结转到下月。增加额度不会给基础免费账号开通 AI，不会更改有效期、启用已暂停账号或赋予管理员权限；需要开通套餐时仍在用户管理中明确设置。

同一 `idempotency_key`（16～128 位字母/数字/短横线/下划线）配合同一内容重试，只返回原台账，不重复加额；相同标识配不同内容返回 409。写入、额度前后快照及审计记录处于同一个 SQLite 事务，防止并发重复点击。

所选月 `credits` 数组不截断。`summary.received_amount_cny` 为该月有金额的人工收款登记合计，`received_unknown_count` 为金额未填的人工收款条数；此数字不是已接入支付平台的实时收入。

## 申请与充值渠道

`GET /v1/account/access` 无需登录，只返回注册与充值的公开渠道，不含用户台账、费率、成本或管理员身份。

`POST /v1/admin/access-settings` 管理员设置：

```json
{
  "registration": {
    "enabled": false,
    "qr_url": "",
    "instructions": "",
    "contact": ""
  },
  "recharge": {
    "enabled": false,
    "qr_url": "",
    "instructions": "",
    "contact": ""
  }
}
```

默认两渠道均关闭，没有二维码。即使管理员打开开关，未配置合规公开 HTTPS 二维码地址时，公共页仍返回 `enabled:false` 和“暂未开放”。关闭时不向公共页返回二维码。支持简短说明与联系文字；不支持上传图片、不请求二维码 URL，不识别支付成功或自动创建账号。二维码仅供联系/人工办理。禁止 HTTP、data、javascript、带凭据、私有 IP、本机/内网域名及非标准 HTTPS 端口；说明和联系文字按普通文本显示。

启用渠道后，用户扫描二维码联系管理员；管理员确认身份或人工收款后，使用现有创建账号、套餐管理或本期人工增额表单办理。没有任何用户端提交的“付款成功”能直接改变权限。

## 后续设计建议

1. 供应商账单对账与异常调用核对；补齐缓存/模型分层计价信息后再提供实际成本分析。
2. 可撤销的人工调账/退款流水，保留原因和审批记录；使用冲正记录，不修改旧流水。
3. 邮件配置完成后开放验证码注册、找回密码；仍保留独立体验赠额与权限控制。
4. 付费回调需验签、订单状态机与幂等确认，再考虑自动到账；本期不把二维码当作支付系统。
5. 账务导出、账期历史快照与管理员角色分工，后续根据实际人数安排。
